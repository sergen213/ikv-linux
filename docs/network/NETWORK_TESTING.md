# Native service, transport and integration testing

All active tests here use explicitly owned localhost services, disposable PostgreSQL, synthetic accounts and ephemeral TLS/signing keys. They never use original credentials, official endpoints or Windows execution. The custom v2 wire is not a recovered original protocol.

## One parent integration batch

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

The full dependency set is in [README](../../README.md). Workers do not run partial build/test/formatter waves while sibling edits are landing. The parent executes once after integration and records actual diagnostics/outcomes. No current cutover test result is inferred from old harness logs.

## Real account/world/persistence suite

```sh
python3 tests/local_multiplayer.py --auth build/ikv-auth --server build/ikv-server \
  --client build/ikv-client --source .
python3 tests/client_eof.py --auth build/ikv-auth --server build/ikv-server \
  --client build/ikv-client --source .
```

Requirements: non-root account, Python3.9+, native `initdb`/`pg_ctl`/`psql`/`pg_dump`/`pg_restore`, `openssl`, Linux `ss` (iproute2), and visibility into the invoking user's owned process socket records under `/proc`. Each run owns a new private temporary directory and Unixsocket-only PostgreSQL cluster (`listen_addresses=''`), generates its own localhost/127.0.0.1 CA/SAN certificates, writes private0600 DSN files, and starts actual native services on OS-assigned loopback ports. Management uses a separate private admin listener. Readiness comes from flushed READY records, not fixed sleeps or stale existing services. Operations have deadlines; captured logs are redacted; processes and clusters are terminated/reaped and temporary credentials removed even on failure. Expanded real admission/backpressure checks have360second outer CTest deadlines, with separately bounded operations.

The suite's explicit assertions include:

- HTTP parser invalid JSON, duplicate length, body/header caps; CA and hostname/IP SAN validation.
- Independent register/login, duplicate/invalid inputs, rejection of public admin-role injection, random salts and hashed—not raw—session persistence.
- Existing-account local admin bootstrap; player-listener404 even for an admin, admin-listener authentication and RBAC.
- AUTH001: hold eight genuinely accepted raw public TCP connections before TLS, confirmed using the owned auth process's kernel socket records; private CA-verified health/login/admin status must complete while the public stalls remain accepted. Queued backlog connections or elapsed-time assumptions do not count as saturation proof.
- AUTH002: twelve malformed role-injection registrations targeting existing admin/victim usernames from one loopback source IP cannot block their valid login from another. Genuine charged login attempts still produce429; exhausted public login quota cannot deny the distinct management login/RBAC or reset operation. Successful reset revokes the old sessions and permits fresh-password login.
- Admin-issued reset token expiry, wrong/single-use token behavior, session revocation after reset/logout, bans/unbans and expiry.
- Character create/list/ownership/name-confirmation/deletion, invalid classes and arbitrary state/outcome injection rejection; live lease prevents duplicate entry/deletion.
- Two authenticated characters in the same authoritative world, bounded/mutually visible movement, local Turkish chat, unauthorized moderation rejection, NPC dialogue, quest acceptance/completion/reward-once, equipment/buffs/resources/cooldowns, range validation, real enemy damage/loot and merchant purchase validation.

- Configured collision correction, zone transfer with AOI removal, admin mute policy, logout/ban removal from the live world.
- Persisted authoritative inventory/quests/location/statistics after reconnect and process restart, followed by actual native-client load of the same saved character.
- Seeded malformed TLS wire peers and simultaneous idle TLS connections cannot kill/starve a healthy session. This is bounded robustness coverage, not a latency/throughput benchmark.

Tests inspect real database records and authoritative outputs; no source-wiring assertions, mock SQL or fake backup markers. The independent gameplay fixtures are NONCANONICAL and cannot prove original formulas/content.
