# Graphics implementation and evidence boundaries

## Native OpenGL asset renderer

`include/ikv/renderer.hpp` defines the shared OpenGL/Vulkan camera, overlay and provider contract. `src/renderer_gl.cpp` is an independent SDL3/OpenGL **3.3 core** provider. It uploads actual decoded original scene vertices, triangle indices and RGBA DDS texels from `Scene`; the former abstract grid/player-marker visualization is not this renderer. No generated substitute world or character mesh is supplied by the renderer.

The provider owns its GL context, programs, VAOs, vertex/index buffers, cached material texture bindings and color/depth framebuffer; the caller owns the SDL window and keeps it alive until provider destruction. Independently written embedded GLSL needs neither Vulkan nor a shader compiler/runtime shader-file search. Entry-point, shader compile/link, resource-boundary, missing-texture, framebuffer and presentation failures are explicit errors, with partial resource cleanup. A new `Scene` uploads everything; actor attach/detach/replacement uploads only the changed actor's meshes and new textures (next paragraph); ordinary animation increments `Scene.geometry_revision` and only meshes whose own `Mesh.revision` changed receive `glBufferSubData`. Static city meshes and original textures are not uploaded every animation frame. Animated instance transforms are consumed directly each frame. `Instance.material` overrides specialize original per-instance lightmaps without duplicating geometry.

**Actor AOI churn keeps zone resources resident (GL, Vulkan, RT).** Every actor entering or leaving the AOI used to bump `Scene::resource_revision`, and both providers then re-uploaded the whole zone (Vulkan 2.4–3.4 s, 4489 meshes / 527 MB, `mode=full`; GL ~0.43 s; RT 8–25 s). In 104 s of Verify2's summon scene, where a Küçük Kertenkele patrols across the AOI edge, that meant 31 full Vulkan uploads after world entry. `resource_revision` is gone. `install_assembly` gives each actor mesh a nonzero `Mesh.key` from the `Scene.mesh_key` counter; zone meshes keep key 0 at fixed indices. Providers record the keys they last uploaded and reload when `Scene.mesh_key` or a vector size changes; `scene_mesh_remap()` then maps each mesh to its previously uploaded index. Retained GL meshes, Vulkan buffers and RT BLAS move to their new indices without validation or upload. Departed actors' buffers are released. RT frees retired BLAS only after the rebuilt TLAS no longer references them, pulsing progress between units, and forces a full TLAS build instead of an in-place update. Textures are append-only and deduplicated by name, so their indices never move. RT triangle records of departed actors stay dead in the shared buffer; once dead records outnumber live ones, the live records are packed into a new buffer. Both the initial and the packed buffers are sized at 2× live, so ordinary churn appends do not copy the zone prefix; only exhausting that headroom repeats the old doubling copy. A new zone still builds a new `Scene` and renderer and uploads everything. `scene_decoder_self_test` (asset-boundaries) runs eight attach/detach/replacement cycles over a keyless zone prefix and asserts that every zone mesh remaps to its own index and only actor meshes upload. After the fix the same scene runs 130+ actor mutations with no full upload after world entry. Vulkan incremental loads take ≤19 ms raster and ≤40 ms with RT, and no attach/detach frame exceeds 200 ms (Vulkan ≤114 ms, RT enhanced ≤160 ms, software-GL 640×480 ≤198 ms). Software GL at 1280×720 already spends ~178 ms on a plain frame, so its attach frames reach ≤237 ms. Evidence and measurements: `analysis/porting-wave4/Stall/summary.json`.

Opaque draws write depth. Recovered blend-enabled materials are sorted by instance origin back-to-front with source `SRCALPHA/INVSRCALPHA` blending and no depth writes; triangle intersections remain a sorting limitation. Original alpha test is `GREATER`, so enabled tests discard final shaded alpha ≤79/255; disabled tests do not discard transparent diffuse texels unconditionally. The source cull state is NONE for double-sided materials, otherwise CCW culling. Native source triangle indices are preserved; **GL counterclockwise front faces** match Vulkan counterclockwise with the shared projection-Y correction and positive-height viewport (see the facing derivation below). UV0/UV1 and decoded DDS row order receive no extra V inversion. Artist-authored DDS mip levels are uploaded directly, not regenerated; original min/mag filters are linear, mip selection nearest, and wrap repeat. Enhanced GL uses trilinear selection of the same original levels.

The scene renders to a retained RGBA8/depth framebuffer, is blitted to the SDL window and presented by `render()`. `screenshot()` reads this actual completed framebuffer and writes top-left P6 PPM, including the real HUD; it does not create a synthetic screenshot or rely on reading an undefined post-swap back buffer. Resizing allocates the framebuffer at the actual pixel extent, validates GPU texture limits, and preserves the previous extent while minimized. The client owns fullscreen/windowed SDL state, high-DPI mouse conversion, settings persistence and resolution selection.

`Overlay` is straight-alpha RGBA8 with a top-left origin. The client rasterizes Turkish text/UI and the provider uploads/composites those actual pixels before presentation. This is a cross-provider UI hook, not recovered original UI layout/font-selection fidelity.

### GL/Vulkan facing regression and visual boundary

The actual pre-fix `analysis/native-render-wayland-proof3/opengl.png` shows an almost-black, blurred world beneath a readable HUD; the corresponding `vulkan.png` resolves the near building's window frames and central lamp, with overlapping black humanoids. Its `evidence.json` records the same Eminonu ADF, AGAH model, 960×640 extent, original appearance and no zone override; the authoritative character IDs differ. These existing frame pixels establish a provider discrepancy, not complete original-world fidelity.

**Correction (user report 1):** the earlier switch to `GL_CCW` was wrong. Source ADF triangles keep D3D clockwise front faces; with CCW both providers culled every exterior surface, so streets/terrain vanished from above, building interiors showed through as untextured gray boxes and actors were drawn inside-out. Vulkan's signed-area sign and the shared projection Y flip do cancel, so both providers use the **same** choice, and that choice is `GL_CW` / `VK_FRONT_FACE_CLOCKWISE`. Verified by HUD-free overhead and street captures under `analysis/user-report-1/worldview/` (terrain visible only from below under CCW, from above under CW).

The shared `scene_source_color_draw()` gate is retained before draw/residency decisions: the original first diffuse handle must exist, and placement material overrides are resolved before this decision. Null-handle geometry remains CPU-side metadata, not a white/black replacement draw. Original shader lighting, homogeneous-clip-Z fog, diffuse/environment alpha, fade/lightmap ordering, DDS mip chains, UVs, RGBA8 non-sRGB output and straight-alpha HUD compositing are unchanged by the facing fix.

Cross-provider pixel identity is not asserted: Vulkan computes normal/environment eye and basis terms in the fragment shader where GL follows source vertex-stage interpolation; Vulkan clamps source fog after interpolation where GL follows source vertex saturation, uses LESS_OR_EQUAL rather than GL's source LESS, and applies optional FXAA through an HDR intermediate. These known implementation differences, unresolved original camera/live environment/action bindings and incomplete scene registration remain separate fidelity gates. The runnable visual regression is the existing native-render integration capture at the same scene/model/camera/extent with GL and original Vulkan; parent must inspect the new actual GPU frame for the same near window/lamp geometry, compare against the saved pre-fix image and record remaining differences. No build, test or post-fix GPU capture was run by this worker.

### Source environment provenance

Static-only Ghidra exports under `analysis/graphics-*` were obtained from the legitimate local unpacked image, never by executing the original PE or contacting official services. `tools/ghidra/GraphicsEvidence.java` records bounded float dumps, references, surrounding instructions and decompiled producers. Updater `0x004b6970` normalizes lighting bytes by exact float32 1/255. That constructor baseline is overwritten every frame from the live environment record (`+0xdc..+0xf0`: ambient, directional, fog colour, lightmap multiplier, fog start/end), whose zone values are not recovered. Shader equations are unchanged apart from the D3D vs_1_1 `oD0` saturation the source pixel shaders rely on.

Original renderer `0x0046fdb0` interpolates SunDir and sky C15/C16 at minute keys0,360,375,555,885,1065,1080,1440. Sun XYZ is normalized; sky byte-like keys use the separately recovered literal0.0039216, not the lighting-byte 1/255. Initializer `0x0041de60` appends paired zone-ID/time vectors: zones0,1,2,3,7,14,15,16,11,12,13,17 use minute749; zones4/5 use590. Float literals `0x0059064c`=749 and `0x005903bc`=590 and insertion helper `0x0041ac00` prove these initial values. The selected **vector index** must not be confused with the zone ID. Frozen startup time is explicitly disclosed; clock advancement is not claimed recovered.

Fog setters `0x0046b630`/`0x0046b660` compute start=raw_start×scale and end=raw_end×scale+110. Root constructor `0x0041da00`, attached to `0x005ea938` at `0x0058b1a5`, initializes scale1. GUI callback `0x00410970` clamps live scale to exact float0.1. This installation has no such loose preference file; scene mode uses the NONCANONICAL daylight environment above instead of the constructor's black fog10..210.

Original sky render uses `T(camera)*R_y(unsigned_tick_ms*5e-6)`, not the item's generic world transform. ## Camera, multiplayer and animation integration

The shared camera uses metres, Y-up, yaw/pitch radians, vertical FOV degrees and column-major matrices. `camera_view_projection()` supplies GL clip Z [−1,1] or Vulkan clip Z [0,1] with Vulkan Y correction. `camera_ground_point()` returns a camera ray intersection with a specified horizontal plane; the client must use recovered scene collision/terrain to choose a valid ground destination. It is not a collision engine.

The original user-guide distinction—ground click for movement and WASD for camera—is a client input requirement, not evidence that the native orbit parameters reproduce original camera numerics. Camera following/orbit limits/collision are client-owned. `Instance.entity_id=0` draws static originals; a nonzero ID draws only when present in the authoritative entity span, applying that entity's X/Z translation from wire millimetres to scene metres. Actual original model assignment belongs to the scene/client owners. Missing model assignment must not silently draw a generated marker. The client calls `update_scene(scene, absolute_seconds)` for recovered transform/skin animation before rendering; providers do not fabricate missing animation clips.

Camera defaults (pitch0.27, distance22, FOV50) frame the ~7.5-unit source actor from behind/above. The original camera (`004773e0`/`00476640`) is `D3DXMatrixLookAtRH` from player+6+distance·(elevation, yaw) to player+6 with up (0,1,0) and `D3DXMatrixPerspectiveFovRH` fovy50/near3/far3000/viewport aspect, so IKV's view math is identical; pitch0.27 is the median view pitch measured from the gameplay video (10–25°, analysis/porting-wave12/WorldTilt/report.md). The old default0.55 (31.5°) leaned screen-edge verticals ~21° versus ~11° in the video. Original limits: mouse-handler distance ±2 in [7.5,60] (`0048435f`), keypad ±2 in [10,45] (`004b74c4`), zone load resets 10 (`0041c9f6`); elevation W/S/arrows in [0.05,1.5208] (`004b7700`), mouse in [−1.57,1.57] (`00484297`); the eye is re-pitched to stay ≥ grid height+3 (`00477b6e`). The wheel zoom keeps a desired distance in [6,60]. Each frame the client casts one ray from the follow target toward the eye against the source `nocamera` collider placements and pulls the eye 1 unit in front of the first hit, so the third-person camera never sits inside buildings.

`tests/render_math_test.cpp` is a focused executable check for GL/Vulkan projection conventions, ground picking, minimized extents, invalid camera values, source fog/color gates and actual scroll UV outputs. Scroll regressions cover first/repeated-tick four-draw consumption, uint32 tick wrap and both velocity boundaries. Existing scene decoder checks cover shared ocean/isik_huzme/case-distinct placements, preserved diffuse/alpha/cull/color residency and deduplicated original bump requests. Build, tests, runtime original-asset screenshots and driver verification are integration-owner work, not observed by this source worker.

## Vulkan and optional ray tracing

`IKV_BUILD_VULKAN` defaults to `ON`: client builds include the real Vulkan renderer/RT sources, compiled shaders and Vulkan loader, and require the Vulkan SDK and `glslc`. Configure with `-DIKV_BUILD_VULKAN=OFF` for an actual OpenGL-only client: no Vulkan renderer/RT sources, Vulkan loader dependency or Vulkan shader compilation are included or required. `ikv-renderers` publishes numeric `IKV_HAS_VULKAN=1` or `0` to consumers; the launcher uses the same build capability. The Vulkan factory declaration and client call exist only when that capability is enabled. Requesting Vulkan in an OpenGL-only build fails explicitly before client window/session setup; it does not select OpenGL while claiming Vulkan. This build gate is separate from runtime Vulkan hardware/RT feature support and does not establish rendered-output evidence.

`src/renderer_vk.cpp` is owned by the separate Vulkan executor. It must use this same scene, camera and overlay contract and never fall back to GL while claiming Vulkan. Runtime extensions/features, resource/swapchain synchronization, actual raster frames and enhanced/RT claims require integration evidence. `RayTracing::required` fails explicitly in OpenGL; automatic mode uses conventional OpenGL rather than implying hardware RT. Vulkan required/automatic feature gating is independently implemented by that provider.

The Vulkan executor reports independent SDL Vulkan surface/swapchain resources, pipelines/cache, HDR intermediate, conventional PCF shadows, recovered-tangent normal mapping, environment lighting, FXAA and bilinear scaling. Enhanced analytic-sky lighting when no environment resource exists is an independent approximation. Both providers consume source vertex-light/fog data, artist-authored mip chains and per-mesh animation revisions. Original variant coverage must be stated per provider and exercised by parent screenshots; GL implementation does not prove Vulkan parity.

**Two frames in flight.** Frame serial *s* records and submits slot *s*&1 (command buffer, fence, acquire semaphore; present semaphores stay per swapchain image), and `render()` waits only for frame *s*−2. Host-written per-frame data is per slot: frame uniforms (one aligned region per slot behind dynamic binding 0 of every set), overlay staging, particle vertices (a buffer a later frame still draws is guarded by its frame serial) and skinned-mesh staging, whose copies are now recorded into the frame instead of a blocking per-frame submit. Post/temporal sets are prebuilt per history index; descriptor rewrites, overlay/particle-texture resizes, new-zone loads and screenshots wait for every frame in flight. GPU-only history (HDR ping-pong, guides, glow `bb38`) stays queue-ordered by the render-pass dependencies, and the swapchain image is acquired before any scene/history change, so an out-of-date swapchain skips a frame without a partial update. Material descriptor sets are cached by their five bound image views (cleared with textures/render targets) and load loops pump the network every 1024 items. Khronos validation 1.4.363 with synchronization validation reported no errors or hazards for original raster, enhanced raster, required RT at scale .5 and 1 (incl. screenshot readback and actor reloads); it found the pre-existing swapchain acquire→layout-transition stage mismatch, now fixed. RX 7900 XTX, 2560×1440 windowed Wayland FIFO, courtyard with bots, A/B against the one-frame build (`analysis/porting-wave9/VkFrames/summary.json`): raster idle/run/combat p99 16.7–21.2 → 11.1–12.3 ms, avg 8.7–10.8 → 7.2–7.7 ms; required RT avg 31–35 → 19–24 ms, p99 50–60 → 40–51 ms (the RT spikes are resolved below).

**Skinned actors and draw order (wave 12).** As original `00476eb0` (it skins a root only while its `+0xf4` frustum flag from `0047c820` is set), the client marks every actor whose padded classes.dat box, swept along its sun shadow (capped at 80 units; RT casts that shadow into view from outside the frustum), misses the view frustum `SceneActorAssembly::skin_held`: `update_scene` keeps advancing its clip clock and bones but skips its CPU skin, so its mesh revision, GPU upload and BLAS refit stay idle. An actor that comes back into view is re-skinned before the frame that draws it (only the released actors when no bone moved). Distant actors are not skinned at a reduced rate: the original skins every visible root each frame (`+0x224` = 1), and the measured per-frame skin motion of actors 80–160 px tall is 8–21 px p95, so a held frame would visibly judder (`analysis/porting-wave12/Perf/impl/`). An uploaded skin swaps its vertex and previous-pose buffers instead of copying vertices into previous first; RT skin refits validate topology once at BLAS build instead of every frame. Opaque draws are sorted nearest-first (ties by material, then mesh) so early Z rejects hidden fragments before their ray queries.

**In-frame actor attach/detach and fast RT zone load.** An actor attach/detach (same `Scene`, retained reload) no longer waits for the device. Its new mesh/texture uploads are recorded into the frame being built (the frame command buffer now begins before any reload). Released buffers and upload staging retire with the frame serial and are destroyed once that frame's fence (which also covers every earlier submission) has signalled. Frame-target descriptor sets stay bound; only material sets are added. RT is then updated inside the same frame by `VulkanRtScene::record_refresh`: kept BLAS move by mesh key, new actor BLAS are built from freshly written inputs, and their triangle records are staged through the per-slot arena behind the existing barrier (in-flight frames may still read the dead records being overwritten). The TLAS is rebuilt in place, because the TLAS and instance buffer are sized for 1.5× the placement bound + 64. Departed BLAS stay alive in a per-slot retirement list until the caller completed that frame, so they are freed after the TLAS no longer references them; noexcept destructors stay callback-free. Only triangle-record packing, triangle-buffer growth and TLAS growth past that bound (rare; growth uses the same bound-based rule on both paths) fall back to waiting for every frame and the synchronous `rebuild()`. A new zone keeps the full path. The full zone rebuild sub-allocates the thousands of per-mesh input/storage/scratch buffers from a few geometrically growing memory blocks instead of one `vkAllocateMemory` each, and builds every BLAS in a single `vkCmdBuildAccelerationStructuresKHR` call. Eminönü RT rebuild: allocation 5.1–5.3 s → 0.10–0.13 s, GPU build 0.92 s → 0.06 s; whole required-RT zone load 8.19–8.44 s → 2.32–2.41 s. The steady-state refresh also pumps the network per 1024 meshes instead of per mesh. The client queue that buffers state while presentation is frozen during a load now folds same-zone mutations under pressure instead of exiting (`ikv::fold_mutation`: latest row per actor, removals and re-adds cancel, events keep order; a zone change never folds; `client-pending-mutations` test). Measured on RX 7900 XTX, 2560×1440 windowed, courtyard with default bots, 12 consecutive entries each (`analysis/porting-wave9/RtFix/summary.json`): zone entry survived 9/12 → 12/12; with an artificial 8 s extra load, 6/6 survived with up to 27 folds. Required RT idle/run/combat avg 21.9–25.5 → 18.5–21.5 ms, p95 44–50 → 20.7–23.1 ms, p99 50–68 → 21.3–24.2 ms, max 59–96 → 22–41 ms. Attach/detach frames cost 2–5 ms and caused no RT fallback. Sync validation (Xvfb, software present) found 0 errors/hazards for raster, enhanced, RT 1 and RT .5, and for the forced fallback paths (TLAS growth, packing).

**RT styles (wave 12, RtLighting).** `rt_style` (`--rt-style`, settings JSON, launcher **Işın izleme ışığı**) selects what RT does:
- **`faithful` (default), original appearance:** the original lighting equation (`f.params.x=0`: `ambd·C17 + saturate(N·Sun)·C18` vertex light, lightmap subtract, record fog, sky/ocean, fake-HDR glow chain, display-referred, no ACES, no denoiser). RT adds what the original lacks and never overrides what it baked: static, Sun-facing surfaces trace one deterministic Sun ray against TLAS instance mask 2 (actors; scenery is mask 1, the source ocean mask 4, `vulkan_rt.cpp`), and an occluded pixel loses only the directional `C18` term (normal-mapped surfaces move to the facing-away end of the I_b/I_c curve). Scenery never occludes: the lightmaps hold its shadows, baked from a light that is not the dynamic SunDir. Day/night follows the server record exactly as in the original.
- **`faithful`, enhanced appearance (waves 21–22):** enhanced direct GGX shading, lightmap subtraction, water, parallax and ACES are kept (`f.params.x=2`). RT replaces the shadow map with a deterministic Sun ray against masks 1|2 and traces one-bounce diffuse GI; outdoor GI replaces baked ambient, while roofed interiors keep their original baked light because artificial-light emission is unknown. The guided temporal/spatial resolve denoises the GI. Water keeps the enhanced analytic reflection rather than physical RT's mirror ray. Until wave 20 this case used the original equation; wave 21 had no GI.
- **`physical`:** the enhanced GGX/GI/reflection path below (with the denoiser). With original appearance nothing would trace, so the device is created without RT and no acceleration structure is built.

The Vulkan frame log reports `rtStyle=` and `lighting=original|enhanced|physical`. Enhanced faithful logs `hardwareRayQueries=1 shadows=1 reflections=0 diffuseGI=1 denoise=1`; original-appearance faithful still has no GI/denoiser. Evidence: `analysis/porting-wave12/RtLighting/report.md` (§1 model, §5 design) and `impl/`; enhanced faithful: `analysis/rt-faithful-enhanced/`, `analysis/porting-wave22-faithful-lightmap/`, `analysis/porting-wave22/Verify/rt/`.

**Fullscreen gamma ramp.** The original calls `0x467030(1,1,1.2)` → `SetGammaRamp` (@0x46711f) in fullscreen: `out = min(pow(c,1/1.2)·1.005, 1)` on display values, scene and HUD. Vulkan applies it in `post.frag` (before FSR frame generation interpolates `output_`, so generated and real frames get it once) and to the HUD texels in `overlay.frag`; OpenGL replaces its final blit with a ramp pass. Windowed output is unchanged.

The physical ray-query path uses genuine acceleration structures for shadows, reflections and one-bounce diffuse hemisphere sampling. Hit lighting uses an explicitly approximate opaque material-color model; this is not full texture/alpha-aware path tracing, source-exact GI or a profiled DDGI selection.

**RT noise correction (wave 10, RtNoise).** The lit RT colour is split as `artwork × (Sun + indirect) + reflection`. The Sun term comes from one deterministic solar-centre ray, so it needs no history and never holds a stale shadow. Only the stochastic indirect gain and the reflection go to scene locations 3 and 4. `temporal.frag` denoises only those two terms (`display = raw + albedo·(indirect′ − indirect) + (reflection′ − reflection)`), so textured artwork is never filtered. The guide is RGBA32F with an octahedral vertex normal, packed 8-bit artwork and signed depth.
- **Temporal accumulation (pass 0):** blends with alpha `1/n` from a per-pixel history length `n` (diffuse alpha), capped at 32 for static diffuse and 16 for animated diffuse regardless of screen speed. Reflections forget after 8 frames and are not clipped: their samples are heavy-tailed, and a neighbourhood clip pulls them toward the median, which darkened actors by about 5%. Diffuse history is clipped to same-surface 5×5 statistics of the raw signal. A 5×5 plane- and normal-weighted prefilter runs before accumulation.
- **Anti-lag:** a 4-frame indirect-luminance history sits in the reflection history's alpha. When the long history differs from it by more than 2σ of its noise, `n` shrinks. A moving caster's indirect contact shadow then clears in a few frames instead of 32.
- **Spatial filter (passes 1–3, RtMotion):** three à-trous B3 iterations (strides 1/2/4) run every frame after accumulation. They follow `history → A → B → A` through `atrous_[4]`, and each pass composes the display colour. Edge stopping uses plane distance and vertex normal. Neighbour weights scale with history length (`n_q/n_p`, and `8/n_p` for the pixel's own history), so fresh pixels draw on converged same-surface neighbours. This design follows the sibling Kabus 22 `rt_filter.comp`. Before it, disoccluded pixels (behind actors under camera orbit, at the leading screen edge) got only the 5×5 filter on 1 spp and ramped over 32 frames: those were the reported noise trails.
- **Reprojection:** bilinear, with each tap validated by previous-camera depth (2% tolerance; 5% for animated draws, whose previous depth is unknown) and normal. Jitter is handled exactly. The pixel shows the unjittered point at `uv − jitter.xy/2`, and static surfaces project it through the jittered `previousVP` to where the previous frame stored it. Animated draws add their unjittered motion vector and `jitter.zw/2`. The old code reconstructed the point at the pixel centre and subtracted the previous jitter, so under FSR its lookup was off by the jitter delta. The measured effect is small: the FSR-quality band error went from 9.61 to 9.34 in the RtMotion ablation.
- **Samples:** per-pixel Cranley-Patterson-rotated integer R2 sequences replace the position hash.
- **Ray origins:** origins are offset along the physical facet normal (`dFdx`/`dFdy`). Normal-mapped samples below the smooth vertex normal's plane are mirrored across that plane, which is continuous across triangles. A ray above the smooth surface but below its facet (the low-poly terminator) starts just under the facet and culls back faces, so it leaves its own hull and only front faces beyond it occlude it. AS instances flip ray facing so source raster front faces are ray front faces. RtNoise mirrored across the facet instead, which shaded every actor triangle differently; RtNoise2 removed that (`analysis/porting-wave10/RtNoise2/report.md`). Each reflection sample's weight is capped at 1, which removes the white sparkles on actors.
- **History reset:** gradual environment drift no longer resets history. The renderer reset all history on any exact change of sun, ambient, fog or sky, and the server day-clock record changes those in small steps. That reset re-noised the whole frame every 5–20 captured frames. Now only changes larger than 2% per frame reset it.
- **Alpha-tested blended surfaces (wave 11 Foliage):** foliage and decals (source cutoff > 0) own the guide. The source's back-to-front order without depth writes makes the last fragment drawn the one the raw colour shows. Their indirect gain and reflection are scaled by coverage, so the resolve replaces exactly their share. Before this, every blended fragment wrote "never history" over the guide of the surface behind it, so trees (including trunks, which share the blended material) and whatever showed through them stayed raw 1-spp noise. That was the reported Vulkan leaf flicker: RT leaf luma std went from 7.8 to 2.2, and with FSR + FG from 7.7 to 0.55 (`analysis/porting-wave11/Foliage/report.md`). Untextured translucent draws keep raw colour and no history. Making leaves invisible to rays raised leaf noise (porous canopy variance), so alpha-aware hits are not a flicker fix. Since wave 13 ray queries alpha-test alpha-tested placements anyway (next item): RT canopies and leaf shadows follow the leaf alpha; leaf noise was not re-measured.
- **Alpha-tested ray hits (wave 13 PhysicalDecal):** placements whose material has the source alpha cutoff are `FORCE_NO_OPAQUE` TLAS instances with their diffuse slot + 1 in the SBT record offset; triangle records carry half2 UVs in `a/b/c.w`; `rtTrace` confirms a candidate only where the diffuse (RT set binding 2, `sampler2D[64]`, mip 3) has alpha > 79/255. Before, the paper-litter ground decals were opaque quads: the street under them lost its Sun ray and every GI/reflection probe and went black in physical style. Cost at 1080p on the RX 7900 XTX: physical +2.5–2.8 ms; the second-order Sun ray from a probe hit stays opaque (saves ~0.5 ms). Faithful (actor rays only) is unchanged (`analysis/porting-wave13/PhysicalDecal/report.md`).
- **Non-finite guide (wave 12 RtLighting):** the guide normal is `rtUnit(worldNormal)`, so a zero/NaN source normal writes (0,1,0) instead of NaN. A NaN guide failed every `<=0` reject, and history plus the à-trous passes grew it into large black rectangles (1.3–1.5 M px at 2560×1440 FSR quality). The `temporal.frag` rejects are also written `!(x>0)`, so any non-finite guide/history is rejected.

Physical-GPU before/after measurements: frozen camera in `analysis/porting-wave10/RtNoise/report.md`, noise in motion (camera orbit plus running actors, deterministic paired replay, bilinear and FSR quality) in `analysis/porting-wave10/RtMotion/report.md`.

Ocean raster/shadow vertices follow the authored displacement, but ray-query acceleration structures still contain undeformed CPU triangles: moving ocean intersections and the approximate opaque hit model are not source-exact water transport. The ocean guide has negative signed depth and no artwork decomposition, so ocean pixels keep their raw colour and use no history.

Goal §11 retains PBR/normal maps/IBL/shadows/HDR/AA/upscaling and optional reflections/shadows/GI with acceleration structures, temporal accumulation, denoising and performance scaling. Implemented Vulkan/RT source and parent-observed capability/frame results must be recorded separately; installed Vulkan libraries are not hardware proof. Unsupported hardware must retain conventional rendering and an explicit capability explanation.

### Texture fidelity and zone-load memory (wave 12, TextureFidelity)

- **Packs.** `texture_detail`/`lightmap_detail` (0..2, settings JSON, `--texture-detail`/`--lightmap-detail`, launcher **Doku detay**/**Gölge detay**) select `*_4/_2/_1.DAT` like the original's TextureDetail/LightmapDetail (`004619d0`). Defaults 2/1 are the original launcher's ≥1700 MB tier (`0x483330`); IKV previously always loaded the `_4` packs, 1/16 of the texels. Lightmaps stay resident in every mode: faithful RT (the default) and original appearance sample them, and as BC1 they cost about 1/8 of their RGBA size.
- **GPU-native BC.** Authored DXT1/DXT3/DXT5 stay compressed: Vulkan BC1-RGBA/BC2/BC3 (`textureCompressionBC` plus linear-filter support), GL `GL_EXT_texture_compression_s3tc`; otherwise both decode to RGBA8 with the CPU decoder. No CPU consumer reads scene texels (alpha test is in the shaders, ray-query alpha tests included). The scene budget (512 MiB) counts resident bytes: Eminönü 68 MB, the largest zone (karakoy) 119 MB at `_1`/`_2`.
- **Zone-load allocation.** A full Vulkan scene load binds every mesh buffer, skin staging buffer and texture into a few per-memory-type blocks (16 MiB doubling to 256 MiB; buffers and images never share a block, so `bufferImageGranularity` does not apply). Each block is freed with its last resource (`shared_ptr`), so retained-reload releases keep their range until then. Retained reloads (actor churn) still allocate per resource and retire per frame. Staging goes through one reusable 64 MiB buffer per load (16-byte-aligned offsets). Eminönü `Vulkan scene resources` went from 2064–2258 ms (HEAD, `_4` RGBA8) to 244–408 ms (`_1`/`_2` BC, 9 memory blocks), with texture upload 87 MB.
- **Anisotropy.** `sampler_` (scene and particle textures) uses `maxAnisotropy = min(16, limit)`; the clamp and shadow samplers do not. GL sets `GL_TEXTURE_MAX_ANISOTROPY` per texture. The original sets D3DSAMP_MAXANISOTROPY (`0046b040`, launcher default 4×); 4× and 16× measured the same in the original-appearance courtyard.
- **FXAA.** `post.frag` skips the directional filter where the 3×3 luma range is below `max(.0312, .125·max)` (FXAA 3.11 early exit), so flat texture interiors are no longer blurred in non-FSR modes.
- **No negative mip bias.** The FSR mip bias stays 0 (wave 11).
- **Evidence.** `analysis/porting-wave12/Textures/impl/`. Under physical RT the user frame matches the research patch (ground/wall/tiles/şadırvan lv 60.8/54.3/534/72.3). Wave-11 orbit with RT + FSR quality: whole-frame flicker 0.99 → 1.81 for reference sharpness 23 → 60 (`_4` → `_1` packs, same build), inside the wave-11 accepted envelope.

### FSR 3.1.4 temporal upscaling (Vulkan)

`--upscaler fsr3` runs AMD FidelityFX Super Resolution 3.1.4 (FidelityFX SDK v1.1.4, MIT, vendored subset in `third_party/FidelityFX-SDK`; source, per-file SHA-256 and four documented local bug-fix patches in its `IKV-PROVENANCE.txt`) after the scene/after passes and before tonemap/HUD. Inputs: jittered (Halton 2,3) render-resolution HDR colour, depth, per-vertex motion vectors (camera, rigid object and skinned previous pose) and a reactive mask (translucent sky layers, particles and contours MAX-blend their coverage; opaque and blended scene meshes overwrite it, see Wave 11 below). Shaders are built by `tools/ffx_fsr3_blobs.py` (glslc + SPIR-V reflection) instead of the Windows-only FidelityFX_SC. Modes Native AA/Quality/Balanced/Performance/Ultra Performance, sharpness 0..1, original and enhanced raster and required RT all run with 0 Khronos validation errors, warnings and sync hazards (owned Xvfb, software WSI, `analysis/porting-wave10/Fsr2/val*`, `motion1`, `skill1`). With `--upscaler bilinear` output is unchanged: against the pre-FSR binary every pixel that is stable across two runs of each binary is identical except on animated actors/shadows (`bilinear-eq1/2`).

Wave 11 (Foliage): blended scene meshes (not sky layers, particles or contours) overwrite motion vectors and reactive like opaque draws, last fragment wins. Alpha-tested ones write reactive 0, untextured ones their coverage. Before, leaves were 0.9 reactive and had no motion vectors, so FSR showed each jittered alpha-test edge (shimmer) and frame generation moved leaves with what lay behind them. Enhanced Vulkan samples mips LINEAR like GL enhanced; original keeps NEAREST. No negative texture mip bias is applied: AMD's −1.58 at Quality measurably raised leaf and ground flicker in motion. FSR depth for leaves (a depth-only end-of-frame draw) made no measurable difference and was not kept.

### FSR 3.1.4 frame generation (Vulkan, IKV-owned pacing)

`--frame-generation on` (settings `frame_generation`, Ayarlar → Kare üretimi, launcher Grafik → Kare üretimi) requires `--upscaler fsr3` (any mode incl. Native AA) and Vulkan; it is off by default. The SDK's optical-flow and frame-interpolation components (vendored unmodified except two local patches, `third_party/FidelityFX-SDK/IKV-PROVENANCE.txt`) run in the frame's command buffer after the post pass; the SDK's Win32-only frame-interpolation swapchain is not used.

- **Inputs:** FI reuses the upscaler's dilated depth, dilated motion and reconstructed previous depth (like the SDK's FSR3 component when it upscales) and interpolates the **HUD-less** tonemapped display image; the current HUD overlay is then drawn onto both the generated and the rendered frame (`hud_pass_`). The HUD is never interpolated; the generated frame shows the newest HUD (the SDK's HUD-less rule). Frames after an FSR history reset show only the rendered frame.
- **Pacing:** a present thread owns the swapchain while FG is active (all queue use under one mutex). Per rendered frame it waits for the frame's fence, presents the generated frame, sleeps half the measured rendered-frame interval minus a 2 ms compositor lead (`IKV_FG_PACING_LEAD_MS` calibrates it), then presents the rendered frame. Presents never wait for display; the user's present mode is kept (FIFO when vsync is on), so FIFO keeps one image per refresh and back-pressures the renderer. Each interval sample is clamped to 1.5× the running interval, so one swapchain/compositor stall no longer doubles the half-interval sleep for ~40 frames (a genuine slowdown still converges at +5% per frame). The render thread waits for at most one queued present job (`drain_presents(1)`): `generated_`/`real_[slot]` are last read by frame *s*−2's job, and waiting for zero measured +9.2 ms per rendered frame for −12 ms submit-to-present latency.
- **Measurement:** on Wayland, display times come from `VK_EXT_present_timing` first-pixel-out timestamps (non-blocking, calibrated to CLOCK_MONOTONIC); the client logs `Vulkan frame generation presents=600 … displayIntervalMs … renderedFrameMs … submitToRealDisplayMs` per 600 presents. `VK_KHR_present_wait` was tried first and rejected: on Mesa 26.2/GNOME Wayland its waits overran their timeout by a refresh and reported in batches, halving the rendered rate.

Physical RX 7900 XTX, Mesa 26.2.4, GNOME Wayland 165 Hz, own disposable stack, windowed 2560×1366, release client, FG off/on interleaved in one stack session (`analysis/porting-wave10/FrameGen/phys1`, `summary.json`); FG-on rows are per 600 presents:

| Mode (idle / run scene) | Rendered fps | Displayed fps | Display interval (ms) |
|---|---|---|---|
| RT required, FSR Quality, FG off | 61.6 / 52.0 | = rendered (FIFO) | — |
| RT required, FSR Quality, FG on | 72–81 / 68–77 | 142–158 / 143–156 | p1 6.059, p50 6.062, p99 12.127 |
| Raster, FSR Quality, 1280×720, FG on | 82.4 (display-bound) | 165.0 | p1 6.059, p99 6.065, sd 0.002 |

FG-off rates on the shared desktop varied between sessions (an earlier pair: 71.4 fps off → 133–149 fps displayed on). Displayed ≈ 2 × rendered; intervals are whole refreshes under FIFO, so a rendered rate below half the refresh gives a 6.06/12.13 ms mix (no VRR). The FI dispatch cost did not lower the rendered rate in these GPU-bound RT runs (the present thread also decouples presentation from the render loop).

**Latency:** the rendered frame is held for half a rendered-frame interval minus the 2 ms lead (≈5 ms at 72 fps) after its GPU work completes, plus the FI dispatch: about half a frame more than FG off. Measured submit→first-pixel-out of rendered frames with FG on: 56–63 ms (includes the FIFO queue depth); the FG-off path has no display-time measurement, so no measured difference is claimed.

Validation: owned Xvfb + `MESA_VK_WSI_DEBUG=sw` + Khronos validation with synchronization validation, FG on in FSR Quality (raster) and FSR Native AA (RT): 0 errors, 0 warnings, 0 sync hazards (`FrameGen/val1`). On Xvfb display timing falls back to present-call times (Mesa's X11 present-timing path faults on Xvfb, so present timing is Wayland-only). The external afmf-linux layer (colour-only, double images) remains documented in `analysis/porting-wave10/Fsr2/afmf1` and is not shipped.

### Intel XeSS: not supported (no Linux runtime)

Checked 2026-10-10 against [intel/xess](https://github.com/intel/xess) v3.0.2 and every release back to v1.1.0. The SDK ships only Windows binaries (`libxess.dll`, `libxess_fg.dll`, `libxell.dll` with `.lib` import libraries); there is no Linux shared library. XeSS-SR has a Vulkan API (`xess_vk.h`), but only through the Windows DLL. XeSS-FG frame generation is D3D12-only (`xefg_swapchain_d3d12.h`; there is no Vulkan FG interface), and XeLL is D3D12/DXGI-only. The native client therefore cannot load XeSS. FSR 3.1.4 upscaling and frame generation above remain the supported path. Revisit this if Intel publishes a Linux Vulkan build.
