# Native Linux client

## Implemented path and evidence boundary

The native C++20/SDL3 application now uses authenticated **custom TLS protocol v2**, not the recovered original LE32 protocol. It consumes the supplied original ADF/DDS scene, original Verdana human-text glyphs with native Unicode fallback, recovered rigid/skeletal animation, original help text and original audio. Its world actions and provisional gameplay configuration are independently implemented and explicitly **NONCANONICAL**; neither original protocol compatibility nor original visual/mechanical parity follows from this implementation.

Current execution evidence comes from the integration owner's [progress ledger](PROGRESS.md) and its retained, scope-labelled artifacts. Source implementation, CPU consumer checks and native framebuffer observations remain separate claims. Current independent **NONCANONICAL** integration acceptance is complete: regular full, GL-only and ASan/UBSan configurations each passed14 tests (42 test runs), with current signed raster/provider-transition and requiredRT/.5 packages passing415.82s/240.60s and raw/guided long-path half/full runs210.51s/193.73s. All Qt/RT images were inspected. These results do not establish GPU-fence semantics, original Windows interoperability, full original visual/mechanical parity or convergence quality. The earlier graceful-stop timeout remains historical/intermittent/unattributed, not an explained production defect; earlier signed326.23s/500.85s results retain historical snapshot scope.

Client files are `src/client_main.cpp`, `src/client_session.cpp`, `src/client_ui.cpp`, `src/client_trade.cpp`, `src/client_charsel.cpp` and `src/audio.cpp`, with matching headers under `include/ikv/`. Scene and renderer implementations are separate owners. Account registration/login are provided by the native Qt launcher and the private HTTPS authentication service; the launcher passes the session on the client's stdin plus the account origin (`--auth`), and the client itself lists, creates, deletes and selects characters over that HTTPS API ([below](#in-client-character-selection-and-creation)).

## Authenticated CLI

```text
ikv-client --host HOST --port PORT --ca CA.pem --session-stdin (--character ID | --auth https://ACCOUNT_ORIGIN)
  [--headless --ticks N --commands commands.json --dx -1|0|1 --dy -1|0|1]
  [--asset-root ORIGINAL_BASE --model-map models.json]
  [--renderer opengl|vulkan --appearance original|enhanced --rt off|auto|required --rt-style faithful|physical]
  [--render-scale .25..1 | --upscaler bilinear|fsr3 --fsr-mode native|quality|balanced|performance|ultra_performance --fsr-sharpness 0..1 --frame-generation on|off]
  [--audio ORIGINAL_MUSIC.ogg --sound-map sounds.json]
  [--settings settings.json --width N --height N --fullscreen --screenshot frame.ppm]
```

Host, CA, session-stdin and either a character ID or (graphical mode only) the HTTPS account origin are mandatory; headless mode always needs `--character`. No official endpoint, anonymous name, password/token argv or unsafe TLS option exists. Port defaults to 7000. Graphical mode additionally requires original assets and a non-null admitted authoritative `source_registry_id`. The asset root accepts direct imported base contents or the original installation's `app/base` directory. Original inputs are read-only and never distributed. The client has no local scene/support-grid/avatar-fallback selector: scene and character assembly follow authenticated state. `--render-scale` is Vulkan-only in [.25,1]; OpenGL requires 1. Window dimensions are 640..3840 by 480..2160.

`--upscaler fsr3` (Vulkan only; OpenGL rejects it) replaces the render scale with AMD FidelityFX Super Resolution 3.1.4 temporal upscaling: `--fsr-mode` picks the render resolution (native = 1.0 "Native AA", quality 1/1.5, balanced 1/1.7, performance 1/2, ultra_performance 1/3 per axis) and `--fsr-sharpness` its RCAS sharpening (0 = off). The HUD is drawn after the upscale at display resolution. The settings JSON keys are `upscaler`, `fsr_mode` and `fsr_sharpness`; Ayarlar's **Ölçekleme** button and **FSR Keskinlik** slider change them live. A device lacking FSR's features, or a context-creation failure, keeps bilinear scaling with a stderr explanation. See [graphics](GRAPHICS_ROADMAP.md#fsr-314-temporal-upscaling-vulkan).

`--frame-generation on` (default off; settings key `frame_generation`, bool) adds AMD FSR 3.1.4 frame generation: one generated frame between rendered frames, about half a frame of extra latency. It requires `--upscaler fsr3` (any `--fsr-mode`, including native); OpenGL and bilinear reject it. Ayarlar's **Kare üretimi** button toggles it live and is inert without FSR; cycling **Ölçekleme** back to Kapalı turns it off. The launcher's **Kare üretimi (FSR 3.1.4)** checkbox stores `graphics/frame_generation`.

Stdin must contain exactly 64 lowercase hexadecimal token bytes and a newline (EOF after the token is also accepted). The launcher supplies this pipe directly; do not put session values in command lines or shell history. A bounded in-memory token is retained for explicit reconnect and cleansed on exit; serialized hello bytes and temporary copies are cleansed. No session value is written to settings, URLs or logs.

OpenSSL verifies the explicit CA chain and the configured hostname or IP **SAN**, rejecting Common-Name-only certificates. TLS 1.2 is the minimum. Graphical startup creates the configured provider, then admits the authenticated state before loading its original Source scene and character assembly; it does not present an offline map as authoritative. CPU/resource work services transport through bounded progress callbacks, while scene/presentation mutations are deferred to stable application boundaries. DNS/connect/handshake and inactivity/write deadlines are five seconds; goodbye/TLS close is bounded to two seconds. Nonblocking WANT_READ/WANT_WRITE retries retain stable buffers. Output is bounded to 262144 bytes/128 frames. Invalid welcome/state/snapshots or truncated frames fail rather than being silently accepted. Only configured, authorized endpoints should be used.

The human HUD selects original `fonts/verdana.ttf`, then original `fonts/verdanab.ttf` if the regular face is absent; it never substitutes `sobee.ttf` when human fonts are missing. ## Native audio and settings

`ikv::GameAudio` (`include/ikv/audio.hpp`, `src/audio.cpp`) is the client audio owner. It reproduces the original sound manager from recovered tables and code; the [audio evidence](evidence/audio-format.md#original-sound-events-and-playback) lists each address.

- **Zone music and ambient beds** (`004573e0`, per frame): the controlled player's world position selects a byte in `musicNN.raw` / `soundNN.raw`, the 2048×2048 grids of the current support zone (`00419a40`; a missing file reads as zero). The cell is `round(x·2/3+1024)`, `round(z·2/3+1024)`. The byte indexes `data/playlist.dat` (61 songs) or `data/playlistsound.dat` (25 beds) in file order. 0 stops, 255 keeps the current track, `nothing` is silent. Music changes only when its index changes and plays once with no loop (`00455eb0`; the stream stops at EOF). The ambient bed restarts while silent, which the native mixer models as a seamless loop. Changes are immediate, with no crossfade. At the Yeni Cami spawn the bytes are music 3 (`music\avlu.ogg`, "courtyard") and ambient 8 (`nothing`). Music volume ≤ 0.01 stops both beds, as the original MusicVolume check does. Without a player the same function plays index 2 (`music\anatema.ogg`), or 8 (`music\istanbulda.ogg`) while the credits window is open, and no ambient; the character screen drives this through `GameAudio::frontend`.
- **Clip sounds** (`0045c980` / `0045cb9e` → `0045c890`): `animation.dat` clips carry `audio`/`audio2`/`audio3`. A clip plays one of them, chosen at random, at the actor's position when a non-looping clip starts, and on every loop wrap of a looping clip. This covers footsteps (Run/Walk → `pc\common_run.raw`/`common_walk.raw`, so they stay in sync with the run cycle), PC punches, kicks, weapon swings and shots, death, resurrection, greet and RP emotes, the rat's bite/damage/die, and NPC and object clips. `scene_animation.cpp` increments `ActorAnimation::audio_cue` at those points; `GameAudio::frame` plays one sound per change for each rendered entity.
- **UI** (`0048eb70` loads them; every user is listed in `docs/evidence/audio-format.md`): toggling a window plays `ui\windowopen.raw` / `ui\windowclose.raw`, any HUD button with an action plays `ui\click.raw`, a Dikkat yes/no confirm (`004b8230`, `ask()`) plays `ui\alert.raw` and its one-button form (character-screen notices, disconnect) `ui\warning.raw`; using an item (`00430610`) and a server-confirmed equip/unequip play `ui\eat.raw`, other confirmed bag/bank moves `ui\itemdrop.raw`; an own critical hit plays `weapon\handgun\ateslisilah1.raw` (original: a channel-9 "Kritik!" line, `0040b170`). The original creates these as DS3D sources without a position. The native client plays them unattenuated and centered [INFERENCE].
- **Skill sounds** (`004a6a80` → `00456c00`): skills.dat `sound`/`femalesound` are decoded into `SourceSkill::sound`/`female_sound` and played at the caster from the skill event.
- **`play_event(name, position)`** takes either an original audio-relative path as written in the source tables or an `audio/sounds.xml` `<Sound>` name. The shipped `sounds.xml` holds only two test entries; a name is resolved by walking its file `chance` values cumulatively [INFERENCE]. Failures are written to `IKV_AUDIO_TRACE`, never thrown.

Level-up, chat and gold/craft/repair sounds have no recovered original trigger: no code references them, and `ui\itemuse.raw`/`kritik.raw` are absent from the executable. They are deliberately left silent.

Mixing: one SDL3 device (S16 stereo 48 kHz) carries the music bed, the ambient bed and 32 one-shot effect voices. When all 32 are busy, a new sound is dropped and traced. Positional voices follow the DirectSound3D configuration recovered from `00454070`/`004596f0`: gain `min(1, 25/distance)` from the camera eye (min distance 25, rolloff 1). A positional mono RAW is two zero-copy SDL streams with output channel maps `{0,-1}`/`{-1,1}`. Their gains apply a balance pan along the camera's right axis, and gains are recomputed every frame as the listener moves. `volume` is the master device gain. `music_volume` (original MusicVolume, Müzik −/+ in the settings window) scales both beds.

Original Ogg/Vorbis is decoded off the frame thread (`std::async`) in-process by the vendored stb_vorbis 1.22 with SDL_mixer's security fixes (CVE-2023-45675..45682; `third_party/stb_vorbis`, wave 17; it replaced a forked `/usr/bin/ffmpeg`, so there is no runtime decoder dependency and no fork of the client, on Linux and Windows alike). Every decoder allocation comes from a fixed 2 MiB arena (the largest original Ogg needs 215 KiB), so a corrupt header cannot size heap allocations. Input is bounded to 32 MiB, output to 600 s at 8–48 kHz. The decoded PCM is one exact-size S16LE stereo buffer at the file's rate (mono is duplicated); SDL resamples it to the 48 kHz device. RAW effect files are cached as shared immutable bytes; the cache resets at 64 MiB and playing voices keep their bytes. A decoder failure is traced and leaves the bed silent.

Original audio RAW under `audio/...raw` uses the statically recovered `0x00453580` format: PCM tag 1, mono 44100 Hz, signed 16-bit little-endian, no header. `audio_asset.cpp` validates the asset path and bounds. Odd-length originals, such as the window open/close sounds, play their whole frames; the incomplete trailing byte is excluded and never padded. Root-level selection grids are not audio. [Audio format evidence](evidence/audio-format.md) distinguishes the proven RAW samples from the grid format.

`--audio` loops one explicit original Ogg in place of grid music. `--sound-map` is an explicit, **NONCANONICAL** operator mapping: a JSON object from world event types to paths under the original `audio/`.

Settings persist only graphics/audio/camera choices, never sessions or authoritative scene/grid/actor selection. Window dimensions, fullscreen, volume, music_volume, backend/appearance/RT, Vulkan render scale and camera yaw/pitch/distance are read from the chosen JSON settings path; explicit CLI values override them. A temporary write is renamed on orderly exit. Changing graphics provider requires restarting through the launcher.

## Deterministic integration interface

Headless mode uses the same authenticated ClientSession and strict state/action codec as the SDL application. `--ticks N` counts received snapshots, not wall-clock loops. One JSON line is emitted for every headless snapshot. Graphical bounded runs additionally retain pending accepted presentation work through departure; snapshot count/READY is not a completed-frame or temporal-quality claim.

```json
{"self":1,"tick":20,"players":[{"id":1,"x":100,"y":0}]}
```

State messages produce `{"type":"state","state":...}` with the world-provided character/entities/events/catalogs. Headless stdout contains only these JSON records; native graphical mode emits `READY client_self=N` after authenticated welcome. EOF before requested snapshots exits nonzero; truncated frames always fail. With no tick requirement, a complete orderly EOF after welcome is accepted.

`--commands` reads at most 1 MiB/4096 sorted entries. `tick` is the one-based received-snapshot count. An entry contains exactly one `action` or `destination`:

```json
[
  {"tick":1,"destination":{"x":200,"y":0}},
  {"tick":15,"action":{"action":"chat","channel":"local","text":"Merhaba"}}
]
```

Destinations are integer custom-world millimetres bounded to ±1536000 by the protocol and further constrained by admitted zone bounds/support. Actions are typed JSON objects whose allowed schemas/authorization are enforced by the world. The optional headless `--dx/--dy` cardinal helper issues 100-millimetre destinations per snapshot, clearly **NONCANONICAL** and never used as native WASD movement.
